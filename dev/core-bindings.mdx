The `com.b44t.messenger` package contains thin Java wrappers around C pointers returned by `deltachat-core-rust`. Each class holds a `long` field (e.g. `contextCPtr`) and delegates all real work to native methods declared with the `native` keyword. The JNI glue lives in `jni/dc_wrapper.c`.

<Warning>
Every object in this layer holds a native resource. Objects are freed in their `finalize()` method, but do not rely on finalisation timing. Avoid creating large numbers of objects without holding references long enough for the GC to process them.
</Warning>

## DcContext

`DcContext` is the central object for a single account. You rarely create it directly — when using `DcAccounts` (the preferred approach for multi-account setups), you get a `DcContext` via `DcAccounts.getAccount(accountId)`.

```java
// Single-account usage (not recommended for new code)
DcContext ctx = new DcContext("Android", "/data/user/0/com.b44t.messenger/files/db.sqlite");

// Multi-account usage (preferred)
DcAccounts accounts = new DcAccounts("/data/user/0/com.b44t.messenger/files/accounts", channel);
DcContext ctx = accounts.getSelectedAccount();
```

### Key methods

| Method | Description |
|---|---|
| `setConfig(key, value)` / `getConfig(key)` | Read/write core configuration keys |
| `isConfigured()` | Returns non-zero if the account has working credentials |
| `startIo()` / `stopIo()` | Start/stop IMAP/SMTP background tasks (use `DcAccounts` variants instead) |
| `maybeNetwork()` | Hint the core that network conditions may have changed |
| `getChat(chatId)` | Return a `DcChat` for the given ID |
| `getMsg(msgId)` | Return a `DcMsg` for the given ID |
| `getContact(contactId)` | Return a `DcContact` for the given ID |
| `getChatlist(flags, query, queryId)` | Return a `DcChatlist` |
| `sendMsg(chatId, msg)` | Send a `DcMsg`; returns the new message ID |
| `imex(what, dir)` | Import or export keys/backups |
| `checkQr(qr)` | Parse a QR code string; returns a `DcLot` with type and data |

## DcAccounts

`DcAccounts` manages multiple accounts stored in a directory. Construct it once at application start:

```java
DcEventChannel channel = new DcEventChannel();
DcAccounts accounts = new DcAccounts(accountsDir, channel);
accounts.startIo();
```

Always use `DcAccounts.startIo()` / `stopIo()` / `maybeNetwork()` rather than the per-context equivalents when running in multi-account mode.

| Method | Description |
|---|---|
| `getAll()` | Returns `int[]` of all account IDs |
| `getAccount(id)` | Returns a `DcContext` for that ID |
| `getSelectedAccount()` | Returns the currently active `DcContext` |
| `selectAccount(id)` | Switch the active account |
| `migrateAccount(dbfile)` | Import a legacy single-account database |
| `removeAccount(id)` | Delete an account |
| `getEventEmitter()` | Returns a cross-account `DcEventEmitter` |
| `getJsonrpcInstance()` | Returns the `DcJsonrpcInstance` used by `FFITransport` |
| `backgroundFetch(timeoutSeconds)` | Run a background fetch for all accounts |

## DcChatlist

A snapshot of the chat list at the time of the call. Retrieve it via `DcContext.getChatlist(flags, query, queryId)`.

```java
// All normal chats
DcChatlist list = ctx.getChatlist(0, null, 0);

// Archived chats only
DcChatlist archived = ctx.getChatlist(DcContext.DC_GCL_ARCHIVED_ONLY, null, 0);

// Search
DcChatlist results = ctx.getChatlist(0, "searchterm", 0);

int count = list.getCnt();
for (int i = 0; i < count; i++) {
    int chatId = list.getChatId(i);
    DcChat chat = list.getChat(i);
    int msgId = list.getMsgId(i);
}
```

### Chatlist flag constants

| Constant | Value | Description |
|---|---|---|
| `DC_GCL_ARCHIVED_ONLY` | 0x01 | Return archived chats only |
| `DC_GCL_NO_SPECIALS` | 0x02 | Omit the "archived" link entry |
| `DC_GCL_ADD_ALLDONE_HINT` | 0x04 | Append the "all done" hint |
| `DC_GCL_FOR_FORWARDING` | 0x08 | Return chats suitable for forwarding |

## DcEvent

Encapsulates a single event from the core. You receive `DcEvent` objects from `DcEventEmitter.getNextEvent()`.

```java
DcEvent event = emitter.getNextEvent(); // null means the emitter was closed
int type       = event.getId();          // DC_EVENT_* constant
int accountId  = event.getAccountId();   // which account emitted the event
int data1      = event.getData1Int();    // first payload integer
int data2      = event.getData2Int();    // second payload integer
String data2s  = event.getData2Str();    // string payload (if any)
byte[] blob    = event.getData2Blob();   // binary payload (e.g. realtime data)
```

The meaning of `data1` and `data2` depends on the event type. For `DC_EVENT_INCOMING_MSG`, `data1` is the `chatId` and `data2` is the `msgId`.

## FFITransport

`FFITransport` bridges the `Rpc` JSON-RPC client to the native core. It extends `BaseRpcTransport` and delegates to `DcJsonrpcInstance`:

```java
DcJsonrpcInstance jsonrpc = accounts.getJsonrpcInstance();
FFITransport transport    = new FFITransport(jsonrpc);
Rpc rpc                   = new Rpc(transport);

// Now use rpc.*() methods
List<Account> allAccounts = rpc.getAllAccounts();
```

`FFITransport.sendRequest(json)` calls `dcJsonrpcInstance.request(json)`, which passes the serialised JSON-RPC request to the Rust core via JNI. `FFITransport.getResponse()` calls `dcJsonrpcInstance.getNextResponse()`, which blocks until the core produces a response.
